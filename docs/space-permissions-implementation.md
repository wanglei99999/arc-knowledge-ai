# 空间权限：首版实现与验收

学习回顾见 [RBAC + ReBAC 学习笔记](rbac-rebac-learning-notes.md)：包含领域关系、递归 SQL、角色计算、业务校验及本次讨论中的易错点。

## 本版能做什么

完整实体关系、授权路径、多部门示例及资源继承图见 [正式设计文档第 6 节：领域模型](superpowers/specs/2026-09-04-tenant-group-space-permission-design.md#6-领域模型)。该文档已同步首版字段、API 和全新初始化流程。

每个用户拥有独立账号，可以加入多个组织；每个组织内可以加入多个群组。部门只是群组的一种用法，组织也不限于公司。

```text
User 全局账号
  └─ TenantMembership 组织内身份
       ├─ GroupMembership → Group（允许多组，父组授权覆盖子组成员）
       └─ 本人授权 / 群组授权 / 组织全体授权
                          ↓ 取最高角色
                        Space
                          ↓ 继承
                    文件、切片、搜索、引用

聊天会话 = 本人拥有该会话 + 当前仍有原空间访问权
```

| 角色 | 阅读、搜索、问答 | 上传 | 删除/重试文件 | 修改空间授权 |
| --- | --- | --- | --- | --- |
| VIEWER | 可以 | 不可以 | 不可以 | 不可以 |
| EDITOR | 可以 | 可以 | 仅本人创建的文件 | 不可以 |
| MANAGER | 可以 | 可以 | 空间内所有文件 | 可以 |

租户管理员管理成员、群组、空间元数据与审计，并不自动拥有私有空间内容权限。需要读取时，必须填写原因，通过明确的“接管”操作获得 MANAGER；接管不会获得其他人的聊天会话。

## 界面入口

- 注册创建全新组织，自动生成公共空间（组织成员 VIEWER）和个人空间（本人 MANAGER）。
- 登录存在多个组织身份时先选择组织。右上角切换组织会取消旧请求/聊天流，清空旧界面状态。
- “权限管理”支持空间模板、分享主体、角色、成员、群组层级与成员关系、管理员接管和审计。
- 文件列表必须选择空间，上传/删除/重试按钮按后端返回的能力显示。前端隐藏按钮不是安全边界；后端逐次校验。
- 成员停用或授权撤销后，下一次请求立即重新判定。已开始的 SSE 按开始时的授权执行，不承诺中途强制收回已传出的内容。

## 初始化（不会自动清旧数据）

1. 将后端 `POSTGRES_URL` 配置为全新、隔离的数据库/schema，并启动运行时依赖。
2. 在后端目录运行 `.venv\Scripts\python.exe -m scripts.migrate`，初始化 v4。
3. 启动 API/Worker 与前端，通过注册页创建组织管理员。
4. 测试员工先注册独立账号；管理员在成员管理按邮箱加入已注册用户，再安排群组与空间授权。

不支持凭 `X-Tenant-Id` 自行加入组织。旧版全局清空、全局模型价格修改不再允许租户管理员调用；其他租户的配置和统计也不可访问。原有开发管理页若调用这些全局操作，会得到 403。

## 验收方式

后端：`.venv\Scripts\python.exe -m pytest tests/unit tests/integration -q`。Windows 临时目录权限受限时，为 pytest 指定工作区内新的 `--basetemp` 目录。真实数据库用例只创建/删除随机命名的独立测试 schema，绝不初始化或清空 public；连接不可用会明确跳过，SQL 或授权失败不会被当作跳过。

前端：`npm test` 与 `npm run build`。

启动真实依赖后，重点验收：

- 两组织同名群组/空间不会串数据；员工多组授权取最高权限。
- 父组空间对子组成员可见，反向不成立；群组移动不能产生环。
- VIEWER 无法上传；EDITOR 无法删除/重试其他成员文件。
- 撤权后文件列表、下载、切片、搜索、聊天、会话历史和引用均不能访问。
- 管理员不能直接读取员工私有空间；接管需要原因且有审计，仍不能读取员工会话。
- 最后一名租户管理员和空间授权的最后有效管理者不会被误删。
- 切换组织时旧 SSE/轮询不会复活；语义记忆和缓存不跨空间混用。

真实 PostgreSQL 的隔离授权测试已完成；尚未完成对象存储、向量库、Redis、Temporal、LLM 与浏览器串联的端到端验收。具体测试证据及限制见 `docs/superpowers/plans/backend-report.md` 和 `frontend-report.md`。
